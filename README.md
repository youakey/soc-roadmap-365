# SOC Roadmap 365

Личный трекер годового плана перехода из «Tech Level 2» в **Junior SOC Analyst**.
52 недели · 631 технический час · 224 задачи · старт 03.08.2026 → финиш 01.08.2027.

Работает без сервера и без сборки: чистый HTML + CSS + JavaScript.
Прогресс хранится в собственном проекте Supabase и привязан к аккаунту, а не к браузеру.
В `localStorage` лежит копия — чтобы приложение работало без сети.

## Деплой на GitHub Pages

### Вариант A — через терминал VS Code (3 минуты)

1. Создай пустой репозиторий на GitHub: **New repository** → имя `soc-roadmap-365` → **Public** → без README.

2. Открой папку проекта в VS Code (`File → Open Folder`), затем `Terminal → New Terminal` и выполни:

```bash
git init
git add .
git commit -m "SOC Roadmap 365"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/soc-roadmap-365.git
git push -u origin main
```

3. На GitHub: **Settings → Pages → Source: Deploy from a branch → Branch: `main` / `(root)` → Save**.

4. Через 1–2 минуты сайт живёт по адресу:
   `https://ТВОЙ_ЛОГИН.github.io/soc-roadmap-365/`

Repository → **Add file → Upload files** → перетащи все файлы → **Commit changes** → дальше пункт 3 выше.

## Про аккаунт и приватность

- Вход обязателен: почта + пароль, с подтверждением по письму. Прогресс привязан к аккаунту — открыл на другом устройстве, вошёл, продолжил.
- PIN убран. Он запирал вкладку, а не данные: код страницы публичный, и любой, кто открыл DevTools, видел его целиком. Ложная защита хуже отсутствия защиты.
- Почта не показывается никому и нигде. В рейтинге — только ник и аватар.
- Заметки, блокеры и отклики лежат в таблице `progress` под Row Level Security: строку отдаёт только тому, у кого `auth.uid() = user_id`. Публичные цифры — в отдельной таблице `public_stats`. Разделение сделано на уровне таблиц, а не полей, поэтому «показать рейтинг» физически не может превратиться в «показать чужие заметки».
- Забыл пароль? На экране входа — «Забыл пароль», ссылка придёт на почту.

## Аккаунт и синхронизация (Supabase)

Прогресс хранится в собственном Supabase-проекте и привязан к аккаунту.
В браузере остаётся копия — приложение открывается и работает без сети,
а накопленное уезжает на сервер, как только связь появилась.

### Что нужно сделать один раз

1. **Создать проект** на supabase.com → New project (имя `soc-roadmap`, регион ближе к Европе).
   При создании Supabase попросит придумать пароль базы данных — сохрани его в менеджере паролей,
   в самом приложении он не нужен.
2. **Выполнить SQL**: Supabase → SQL Editor → New query → вставить содержимое `supabase.sql` → Run.
   Создаёт таблицы, политики RLS, триггер профиля и строку трека.
3. **Прописать адреса возврата** — Supabase → Authentication → URL Configuration:
   - **Site URL:** `https://youakey.github.io/soc-roadmap-365/`
   - **Redirect URLs:** тот же адрес и `http://localhost:*` для локальной разработки

   Без этого шага письмо приходит, но ссылка в нём ведёт на `http://localhost:3000` —
   Supabase подставляет его по умолчанию. Регистрация выглядит сломанной,
   хотя аккаунт уже создан. Делать это **до** первой регистрации.
4. **Забрать ключи**: Supabase → Project Settings → API → скопировать `Project URL` и publishable-ключ.
5. **Вписать их в `config.js`** вместе с `SITE_URL` и закоммитить.

### Почему anon-ключ можно держать в публичном репозитории

Так задумано в Supabase: `anon` — это не секрет, а идентификатор проекта.
Доступ к данным режет **RLS на стороне сервера**: политики в `supabase.sql`
разрешают читать и писать строку только тому, у кого `auth.uid() = user_id`.
Без входа в аккаунт по этому ключу не получить ничего.

### Как пользоваться

Открыл сайт → **Создать аккаунт** (ник, аватар, почта, пароль) →
письмо с подтверждением → ссылка из письма возвращает уже внутрь трекера.
На втором устройстве — вход той же почтой. Дальше всё само:
отправка через 2 секунды после изменения, приём — при открытии.

Письма шлёт встроенная почта Supabase — около трёх штук в час.
Для двух устройств этого хватает; перед публичным запуском нужен свой SMTP.

**Слияние, а не затирание.** Отметки задач объединяются, галочки дня
складываются по блокам, статус «Закрыта» не откатывается назад,
отклики склеиваются по id.
